# AlumNU — System Requirements

This is Part 4 of our Requirements Specification report. It is the contract the finished interface is tested against. The state diagrams it cites (D1–D3) are in the report.

Every requirement below is written as **[Trigger / Condition] → [Observable Behavior]**. Each one can be confirmed or refuted by a test.

**How to read the tables**

- **ID**: the area letter plus a number (F-D3 = Functional, Search, #3). Every automated test name in `tests/` starts with the ID of the requirement it verifies (e.g. `it('F-D2: filters by major')`), so searching the repo for an ID finds its tests.
- **Priority**: **Must** = required for a working system. **Should** = a planned enhancement. **Nice** = a stretch goal.
- **How to test**: the kind of test and what it checks.
  - **Unit** = a Vitest test that calls the fake API directly (`tests/api/`).
  - **Component** = a React Testing Library test that renders the real app with `renderApp(route, { as: user })` and interacts with it the way a user would (`tests/pages/`, `tests/routing/`).
  - **E2E** = a Playwright test in a real browser, for things jsdom cannot measure (layout, viewport size, timing).
  - **Manual** = a checklist step performed by a person.
  - ✅ = the automated test already exists and passes in the repository today.
- **Source**: where the requirement comes from.
  - **D1 / D2 / D3** = State Diagram 1 (Login & Sign-up), 2 (Home, Search & Messages), or 3 (Calendar & Profile), with the state or transition name in quotes.
  - **TF#** = a finding from our low-fidelity prototype testing (listed below).

**Prototype testing findings (TF) referenced below**

| TF  | What testers did or said                                                                                               | Design change it led to                                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| TF1 | Went to Settings to edit their profile. "View Profile" didn't suggest editing, and the small pen icons went unnoticed. | Visible text "Edit" buttons on every profile section, "View/Edit Profile" in the menu, "Edit Profile Here" link in Settings |
| TF2 | Couldn't tell "Request Coffee Chat" from "Send Message," and expected a coffee chat request to let them pick a time.   | Only alumni send coffee chat invites, and invites include a date and time. Each contact button gets a one-line description. |
| TF3 | Networking status didn't show whether one or several options could be picked, and the wording didn't fit its audience. | A single-choice radio group, written for alumni, with a commitment description on each option                               |
| TF4 | "Type" on the social-links step was vague ("does it mean LinkedIn?").                                                  | Renamed to "Platform" with examples                                                                                         |
| TF5 | Sign-up had no visible way to go back a step.                                                                          | A Back button on every sign-up/onboarding step                                                                              |
| TF6 | No way to search by combined major, and alumni onboarding had no experience step.                                      | Combined-major filter. New alumni Work History step.                                                                        |
| TF7 | _(What worked)_ Testers found alumni profiles and contact options without help.                                        | Keep search → profile → message to three clicks or fewer                                                                    |
